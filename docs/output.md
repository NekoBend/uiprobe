# Output formats

## JSON documents

Every JSON document has a `schema` field. Its number changes only with an incompatible change, such as a removed or renamed field or a field whose meaning changes. A new field does not change it, so a reader should ignore fields it does not know.

- `uiprobe.screen/1`: a dumped screen with `captured_at`, `device` (`serial`, and `api_level` when known), `app` (`package`, and `activity`, which is left out when the focused activity cannot be read reliably or belongs to another app; it is read from Android's text diagnostics on a best-effort basis, so treat it as a hint, not as a security signal), `screen_id`, `display` (`width`, `height`; the device's current logical display size, from `wm size` rotated to the current orientation, falling back to the extent of the dumped windows when that cannot be read), and a flat list of `elements`. Each element has an `id` (`e1`, `e2`, ...), the `id` of its `parent` (absent for top-level elements), `class`, `bounds` as `[left, top, right, bottom]`, and, when present, `text`, `resource_id`, `content_desc`, `hint`, and `flags`. `screen_id` is a short hash of the package, activity, and the classes and resource ids of the elements; it does not change when only text or positions change, but it does change when the number of elements changes.
- `uiprobe.screenshot/1`: the result of `uiprobe screenshot -o PATH --json`, with `captured_at` (as in `uiprobe.screen/1`), `device` (`serial`), `path` (as given with `-o`), `bytes` (the size of the file), `width` and `height` (of the image, in pixels) and `display` (`width`, `height`: the display size that `uiprobe.screen/1` reports and that tap coordinates use, from `wm size`, turned to the orientation of the image; left out when it cannot be read). On newer Android a screen that forbids screenshots can give a mostly black image, which is still a valid PNG and is saved.
- `uiprobe.find/1`: the result of `uiprobe find --json`, with `screen_id`, `criteria` (the given ones, by the element's key names: `text`, `resource_id`, `content_desc`), `total` (how many elements matched), and `elements` (the matches, at most 20, possibly empty). Each element has the same form as in `uiprobe.screen/1` plus `center`, `[x, y]` (left out when the element cannot be pressed: covered, or no press target).
- `uiprobe.action/1`: the result of `uiprobe tap`, `swipe` and `key` with `--json`. `action` is `tap`, `long_tap`, `swipe` or `key`. A tap has `point` (`[x, y]`, the point that was pressed) and, when an element was selected, `element` (the same form as in `uiprobe.find/1`, with `center`; without an element, `--xy`, the key is absent). A swipe has `from` and `to` (`[x, y]`), `duration_ms`, `direction` (only with `--direction`) and `element` (only when one was selected with `--direction`). A key has `key`, the key code name that was sent.
- `uiprobe.crawl_preview/1`: the result of `uiprobe crawl PACKAGE --json` (with or without `--dry-run`), with `package`, `screen_id`, `captured_at` (as in `uiprobe.screen/1`), `settings` (the path of the settings file that was used), `pressed` (`false`, because nothing is pressed) and `mode` (`"preview"`), which this version always writes and which `uiprobe.crawl_preview/1` documents from earlier versions may omit, `foreground` (the package in front; left out when unknown), `keyboard_shown` (`true` or `false`; left out when unknown), `press` and `skip`. Both arrays are always written, in the order of the screen, and may be empty. `press` holds the elements a crawl would press, in the form of `uiprobe.find/1` elements with `center` (the point the judgement chose; a pressable element is never covered, so it always has one). `skip` holds the others in the same form (`center` is left out when the element has no visible part of at least `[rules] min_visible_px` pixels (default 8) in width and height, reason `not_visible`, or is covered; on a `screen_too_large` screen the center is the middle of the visible part with a fixed 8 pixels, and the cover is not computed) plus `reasons` (the reasons, in the order of the table in [Previewing a crawl](crawl.md)) and `details`, a list with one object per detail: `reason` and, when not empty, `word`, `field`, `element_id` (the element where the word or the cause was found) and `note`.
- `uiprobe.init/1`: the result of `uiprobe init --json`, `{"schema": ..., "path": ...}`, the path of the settings file that was created.
- `uiprobe.devices/1`: `{"schema": ..., "devices": [...]}` with `serial` and `state` for each device, and `model`, `api_level`, and `emulator` when known.
- `uiprobe.error/1`: `{"schema": ..., "error": {"code": ..., "message": ..., "details": ...}}`, where `details` is present only when there are any. Without `--json` the message is printed on stderr instead.

The files of a crawl run folder (`uiprobe.run_start/1`, `uiprobe.transition_start/1`, `uiprobe.transition_end/1`, `uiprobe.skip/1`, `uiprobe.run/1`) are described in [The run folder](run-folder.md).

## Exit codes

| Code | `error.code` | Meaning |
| --- | --- | --- |
| 0 | | Success. This includes a crawl preview that found nothing to press. |
| 1 | `internal_error`, `file_error` | Unexpected error. `file_error` is `uiprobe screenshot` failing to create its file (`details.created` is `false`) or to finish writing it (`true`; the partial file stays and `details.path` names it). |
| 2 | `usage_error` | Bad command line or argument. |
| 3 | `adb_server_unavailable` | The adb server cannot be reached or started. |
| 4 | `device_not_found`, `multiple_devices` | No device matches, or several are ready and none was chosen. |
| 5 | `device_offline`, `device_unauthorized` | The device is connected but not usable. |
| 10 | `adb_error` | The adb server refused a request or the protocol broke. |
| 11 | `dump_failed` | `uiautomator dump` failed, timed out while running, or produced unusable XML. |
| 12 | `element_not_found`, `element_not_visible` | `find_one`, `uiprobe tap` or `uiprobe swipe --direction` found nothing (`uiprobe find` exits with 0 instead), or the element to press has no visible part, shows under 8 x 8 pixels (also when it is the only match), is covered by another element, or has no press target (`uiprobe tap` with a selector, and the library). |
| 13 | `multiple_elements` | `find_one`, `uiprobe tap` or `uiprobe swipe --direction` found several elements (a match under 8 x 8 pixels counts). |
| 14 | `input_failed` | The device did not report success for a tap, long press, swipe or key. This does not prove that nothing was pressed or moved. |
| 16 | `screenshot_failed` | The device gave no usable screenshot: empty output (a screen that forbids screenshots can give this on older Android), a cut-off image or data that fails the PNG checks listed in [Taking a screenshot](commands.md#taking-a-screenshot). No file is made. `uiprobe dump` can still return the structure of that screen. |
| 130 | `interrupted` | Interrupted with Ctrl+C (also during `crawl`). When `uiprobe screenshot` is interrupted while it writes its file, `details.path` names it and `details.created` is `true`; the file stays and may be incomplete. A Ctrl+C at another instant (inside the creation itself, or after the file is complete while the result is printed) may only say "interrupted" and can leave a partial or a complete file. |
