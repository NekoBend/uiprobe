# Network and privacy

- uiprobe connects only to the adb server, which is on `127.0.0.1:5037` unless you choose another address. It makes no other network connection and no DNS lookup: the host of the address must be an IP address or `localhost`, and any other host name is rejected as a usage error before anything is sent. `localhost` is mapped to `127.0.0.1` without a lookup.
- When uiprobe starts the adb server itself, it runs `adb start-server` with `ADB_MDNS=0` and without `ADB_SERVER_SOCKET`, `ANDROID_ADB_SERVER_ADDRESS` or `ANDROID_ADB_SERVER_PORT`, so the started server never gets an address variable from the environment (including an empty `ANDROID_ADB_SERVER_ADDRESS`), and that server sends no mDNS queries to the local network. That server keeps running after uiprobe exits, like any adb server. Because mDNS is off, it does not find wireless-debugging devices automatically (USB devices and emulators are unaffected, and `adb connect HOST:PORT` still works). To get the default behavior back, stop the server with `adb kill-server`, unset `ADB_MDNS` if it is set, and start the server yourself with `adb start-server` before you run uiprobe; uiprobe sets `ADB_MDNS=0` only when it starts the server itself. This was checked with Platform-Tools 37.0.1.
- A server you start yourself sends mDNS queries unless `ADB_MDNS=0` is set when it starts. `adb start-server` does nothing when a server is already running, so stop that one first: `adb kill-server`, then `ADB_MDNS=0 adb start-server`. In PowerShell, set the variable first: `$env:ADB_MDNS = "0"; adb kill-server; adb start-server`. `adb mdns check` reports whether discovery is disabled.
- The emulator or device and the apps under test have their own network traffic. uiprobe does not control it.
- A dump contains whatever text is on the screen, including personal data such as names, addresses, and messages. Treat saved screens accordingly.
- Android lets an app forbid screenshots of a screen (`FLAG_SECURE`), but `uiautomator` still returns that screen's structure and text. So a dump of such a screen, and any copy of it you save, contains that text, which may include personal data. For example, on Android emulators at API 24 and API 36, Chrome's Incognito tab had `FLAG_SECURE`: Android's screenshot command, `screencap`, gave empty output on API 24 and an almost entirely black image on API 36, while `uiautomator dump` and `uiprobe dump` returned the full tree with its text.
- During a dump, uiprobe writes one temporary file, `/data/local/tmp/uiprobe-<random>.xml`, on the device and tries to remove it afterwards. If the device disconnects or the adb server stops during a dump, the file can be left behind; `adb -s SERIAL shell 'rm -f /data/local/tmp/uiprobe-*.xml'` removes it (add `-H HOST -P PORT` if you gave uiprobe another adb server address).
