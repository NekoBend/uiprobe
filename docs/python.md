# Python API

```python
from uiprobe import Device

device = Device()  # or Device("emulator-5554")
screen = device.dump()

print(screen.package, screen.activity)
login = screen.find_one(resource_id="login")  # exactly one match, or an error
print(login.text, screen.tap_point(login))  # the point to tap; raises when covered

buttons = screen.find(text="ログイン")  # a list, possibly empty
print(screen.to_json(indent=2))

point = device.tap(login)  # press it; returns the point pressed
# device.tap(screen.tap_point(login), long=True)  # instead of the tap above: the same point, held 800 ms
```

`Device(serial=None, *, adb_server=None, adb=None, start_server=True)` chooses the device when it is created. `uiprobe.devices()` lists devices. `Screen.find` selects visible elements (8 x 8 pixels or more) and `Screen.find_one` selects one element, both with the matching rules of `uiprobe find`: `text`, `resource_id` and `desc` are given together and must all match (AND). `text` is equal after surrounding whitespace is removed on both sides, `resource_id` is equal to the full id or the part after `:id/`, and `desc` is equal. `Screen.visible_bounds(element)` returns the visible part of an element, or `None` when nothing of it is on the display or the part is narrower or lower than `uiprobe.model.MIN_VISIBLE_PX` (8) pixels. `Screen.require_visible(element)` returns the visible part or raises `ElementNotVisibleError` (`no_visible_part` or `too_small`); `Element.is_meaningful` is true for an element that is clickable or has a non-empty text, content description or hint. `Screen.hit_target((x, y))` returns the topmost meaningful element (clickable, or with a non-empty text, content description or hint; the last in document order) whose part on the display holds the point, or `None`; any meaningful element on top counts, whatever its size (the 8-pixel minimum applies to the element being pressed), the right and bottom edges are exclusive and an empty part never holds a point. `Screen.find_one` counts the matches over every element with a non-empty part on the display, whatever its size, so a 100 x 100 element and a 100 x 7 one with the same text are two matches (`MultipleElementsError`); a single match under 8 x 8 pixels raises `ElementNotVisibleError` (`too_small`), not `ElementNotFoundError`. When `find_one` raises `ElementNotFoundError` or `MultipleElementsError`, the `details` of the error hold `criteria`, `total` and `candidates`: for `multiple_elements` the matches, for `element_not_found` the visible elements whose text, resource id or description contains a given value (compared after Unicode NFKC normalization and case folding), or, if there are none, the clickable ones that are not disabled. The `criteria` in `details` use the JSON names (`text`, `resource_id`, `content_desc`), as in `uiprobe find --json`, although the Python parameter is `desc`. There are at most 20 candidates, and `total` is their full number. A candidate has the JSON form of an element plus `center`, `[x, y]`, which is left out when the element cannot be pressed (no visible part, too small, covered, or no press target). `Device(...)` and `devices(...)` raise `TypeError` for an argument of the wrong type and `ValueError` for a malformed address or adb path, before contacting the adb server. `find` and `find_one` raise `ValueError` when no criterion is given. `Screen.tap_point(element)` returns the center of the visible part, rounded down, as `(x, y)`; `find` reports the same point as `center`. It raises `ElementNotVisibleError` (`element_not_visible`, with `element`, `bounds` and `reason` in `details`) when the element has no visible part (`no_visible_part`), shows under 8 x 8 pixels (`too_small`, plus `visible_size`) or is covered (`covered`, plus `covered_by` and `point`) or has no press target (`no_target`, plus `point`): `hit_target` at the point must be the element or one of its descendants, so an element that is not meaningful (no text, description or hint, not clickable), for example one selected by its resource id inside a clickable row, is refused, naming the row; press the row instead. When `hit_target` is `None` (no meaningful element holds the point, possible only for an element that is not meaningful itself) the element is refused with `no_target`, because nothing at that point can receive a press.

`Device.dump(*, details=True)` captures the screen. With `details=False` it skips the reads of `dumpsys window` and `getprop`, so `Screen.activity` and `Screen.api_level` are `None` (the JSON form then leaves out `app.activity` and `device.api_level`) and `Screen.screen_id`, which includes the activity, can differ from the id of a full dump of the same screen; a `details` that is not a bool raises `TypeError` before anything is sent; the display size (`wm size`) and everything that `find_one`, `tap_point` and `tap` check are still read, so those checks give the same results. `uiprobe tap` and `uiprobe swipe` with a selector use `details=False`; `uiprobe dump` and `uiprobe find` keep the default.

`uiprobe.__version__` is the version string, such as `0.1.0a1.dev0`, that `uiprobe --version` prints.

`Device.tap(target, *, long=False, press_ms=10)` presses one point and returns it as `(x, y)`. By default the tap holds still for `press_ms` = 10 ms and is sent as `input swipe X Y X Y 10`, so the "Pointer location" developer option shows it (a plain `input tap` is barely visible there); the point does not move. `press_ms` is an int from 0 to 200 (a bool is not an int; `TypeError` for another type, `ValueError` outside the range): 0 sends the plain `input tap X Y`, and the bound stays below Android's usual default long-press time (about 400 to 500 ms, longer with accessibility settings), though an app may use its own shorter threshold. The 10 ms visibility was measured on one device only (a Galaxy S25 Ultra at 60 Hz: 10 ms visible, 6 ms not). `long=True` sends the fixed 800 ms press and cannot be combined with a `press_ms` other than 10 (`ValueError`). `Device.tap` validates `press_ms` before this call sends any adb request (creating `Device()` already contacts the server). `target` is an `Element` or a point, a tuple or list of two ints from 0 to 32767 (a bool is not an int here). A point of the wrong type, or a `long` that is not a bool, raises `TypeError`; a coordinate out of range raises `ValueError`; `Device.tap()` validates these arguments before it sends any adb request of its own. An element is accepted only when it is one of the elements of the `Screen` returned by the latest `device.dump()` of this same `Device` (the same object, not a copy; `Screen.find` and `Screen.find_one` return such objects). The point is then `screen.tap_point(element)`, so `Device.tap`, `uiprobe tap` and the `center` of `find` agree. An element from an older dump, from another `Device`, built by hand, or given before any dump raises `ValueError` before anything is sent: dump again, or pass `screen.tap_point(element)` as a point. An element with no visible part, a sliver under 8 x 8 pixels or a covered element raises `ElementNotVisibleError` and nothing is sent. A point given directly is pressed as given, with no such check, because the caller named it. The input is sent once and never retried or resent, not even after a connection error, which propagates unchanged. When the device does not report success, `Device.tap` raises `InputFailedError` (`input_failed`); success needs the line `uiprobe-exit:0` as the last line and no other line that is not empty (empty lines are ignored); its `details` hold `command` (`tap` for any `press_ms`, or `long_tap`), `point`, `reason` (`no_exit_status`, `exit_status` or `unexpected_output`), `exit_status` for the second reason, and `output` (at most 200 characters) when there is other text. `input_failed` does not prove that nothing was pressed, so do not repeat the tap blindly. The app in front is not checked.

`Device.swipe(start, end, *, duration_ms=300)` drags one finger and returns `(start, end)` as tuples of ints. Both points follow the rules of `tap` (a tuple or list of two ints from 0 to 32767, no bool); `duration_ms` is an int from 1 to 10000 (`TypeError` for another type, `ValueError` outside the range). A swipe whose start equals its end is a `ValueError`: it is a press, use `tap`. Everything is checked before the adb server is contacted. It sends `input swipe X1 Y1 X2 Y2 MS; echo uiprobe-exit:$?` once, with a read timeout of `duration_ms / 1000 + 10` seconds, and never resends it. `InputFailedError` has `command` `swipe`, `from`, `to` and `duration_ms` in its `details` instead of `point`, and does not prove that nothing moved.

`Device.scroll(direction, *, within=None, duration_ms=300)` swipes along the middle of an area of the screen of the latest `device.dump()` and returns the same pair as `swipe`. `direction` is the way the finger moves: `"up"`, `"down"`, `"left"` or `"right"` (a non-str raises `TypeError`, another string `ValueError`). Without a dump it raises `ValueError("dump the screen first")`. `within` must be an `Element` (`TypeError` for any other type) of that latest screen (an `Element` from another dump raises `ValueError`, as for `tap`) and its visible part is the area (`ElementNotVisibleError` when it has none, a sliver under 8 x 8 pixels included; a cover is not checked); without `within` the area is the whole display. The geometry is the one described under [Swiping and scrolling](commands.md#swiping-and-scrolling): the gesture runs from the first to the last pixel of the rectangle (right and bottom are exclusive, so the far ends are `right - 1` and `bottom - 1`, and both ends are inside the area); an area that is too small raises `ValueError("the area is too small to scroll")`, and so does a latest dump whose display size is unknown because `wm size` could not be read (`ValueError("the display size is unknown ...")`; use `swipe` with explicit points). All of this is checked before anything is sent; the swipe then follows the rules of `Device.swipe`.

`Device.scroll_display(direction, *, duration_ms=300)` is `scroll` over the whole display without a dump: it reads the current display size once with `dumpsys window displays` (the `cur=` size of display 0, already rotated), then sends one swipe with the same geometry and checks as `scroll` without `within`, and returns the same pair. It needs no earlier `dump()` and does not change the latest dump. A `direction` of the wrong type raises `TypeError`, another string `ValueError`; `duration_ms` is checked like in `swipe` (a wrong type raises `TypeError`, an unusable value `ValueError`), before the display size is read. When the size cannot be read it raises `ValueError("the display size is unknown ...")` (a `uiprobe.device.DisplaySizeUnknownError`, a subclass of `ValueError`) and sends nothing; it does not fall back to a dump by itself, so call `dump()` and then `scroll`, or use `swipe` with explicit points. A display too small to scroll raises `ValueError("the area is too small to scroll")`. All of this is checked before any input is sent.

A `Device` object can be reused for several actions: the device is chosen once, when the object is created, so later actions do not repeat the device lookup (`host:devices-l`).

`Device.key(name)` presses one key and returns the key code name it sent. `name` is a key of `uiprobe.device.KEY_ALIASES` (case-insensitive) or a full `KEYCODE_[A-Z0-9_]{1,40}` name; a non-str raises `TypeError`, and an empty name, a number, a `KEYCODE_` name made only of two or more digits (such as `KEYCODE_26`; `KEYCODE_0` to `KEYCODE_9` are accepted), a lower-case `KEYCODE_` name or anything else raises `ValueError`, before the adb server is contacted. It sends `input keyevent KEYCODE_...; echo uiprobe-exit:$?` once and never resends it; `InputFailedError` has `command` `key` and `key` in its `details`. `KEY_ALIASES` is the alias table in [Pressing keys](commands.md#pressing-keys), a `tuple` of `(alias, key code name)` pairs, so it cannot be changed. A key in `uiprobe.device.DEVICE_WIDE_KEYS` (a `frozenset` of names) or starting with one of `uiprobe.device.DEVICE_WIDE_KEY_PREFIXES` (a `tuple`) acts on the whole device and raises `ValueError`, before the adb server is contacted. `Device.key(name, *, refused=None)` takes the refused names from `refused`, a `uiprobe.device.RefusedKeys(keys, prefixes, source="the refused-keys list")` (a `frozenset` of exact `KEYCODE_` names and a `tuple` of name prefixes, each checked against `KEYCODE_[A-Z0-9_]{1,40}`; `source`, a `str`, only names the origin of the lists in the refusal message, which for an exact key says to remove it there and for a prefix names the prefix and says that changing it affects every key that starts with it), in place of those two built-in lists; `None` keeps them. The keys of `uiprobe.device.FIXED_DEVICE_KEYS` are refused whatever `refused` holds, and a `refused` of another type raises `TypeError`. The settings file's lists are `RefusedKeys(frozenset(settings.refused_keys), settings.refused_key_prefixes, str(settings.source))`. The app in front is not checked by `swipe`, `scroll` or `key`.

`Device.type_text(text)` types printable ASCII (0x20 to 0x7E) into the field that has focus and returns `None`. A non-str raises `TypeError`, and a str subclass is read once as a plain `str` with the same characters; empty text, a character outside ASCII, a newline, a tab or another control character raises `uiprobe.device.TextNotTypedError` (a `ValueError`) before the adb server is contacted, with `details` holding `character`, `escaped` and `position` for a refused character. It sends `input text` with the argument in single quotes and `; echo uiprobe-exit:$?`, once per piece, in pieces of at most `uiprobe.device.TYPE_PIECE_SIZE` (256) characters, and splits the text between `%` and `s` so that no piece contains `%s` (the device turns it into a space). Each piece must report exit status 0 and print nothing else (empty lines are ignored), or typing stops with `InputFailedError` (`details`: `command` `type`, `reason`, `piece`, `pieces` and `pieces_done`; no exit status, as the device prints it and a reply could repeat the text). A device error while sending is raised as a new error of the same class whose message and `details` hold only fixed words and the numbers `piece`, `pieces` and `pieces_done` (and `request` `shell:input text <text omitted>`), never the text or what the device answered, chained to no error that uiprobe caught. Typing is not checked afterwards. Typing that stops can leave the earlier pieces typed and the piece it stopped at typed in part or in full.

`Device.launch(package, *, restart=False, timeout=10.0)` starts an app and returns `None` once it is in front. `package` must be a `str` (`TypeError` otherwise; a subclass is used as a plain `str` with the same text) that follows the same rule as `preview` (`ValueError` otherwise), `restart` a bool and `timeout` a number of seconds from 0 to 600 (a bool is not a number; the value checked and used is the one the base `int` or `float` type gives); all are checked before the adb server is contacted. With `restart=True` it first sends `am force-stop PACKAGE; echo uiprobe-exit:$?`, which stops the app so the next launch starts a fresh task (unsaved state in the app is lost); it must report exit status 0 and print nothing else (empty lines are ignored), or monkey is not sent. It then sends exactly `monkey -p PACKAGE -c android.intent.category.LAUNCHER 1` once, never resent, and requires the line `Events injected: 1` exactly once. Then it reads `device.foreground()` about every 0.5 seconds, at least once, until it equals `package`; no read starts after `timeout` seconds, which bounds when the last read may start, not the whole wait (a read that started in time still counts, and a pause can end late). A launch that cannot be confirmed raises `LaunchFailedError` (`launch_failed`, exit code 15), whose `details` hold `package` and `reason`: `stop_failed` (plus `exit_status` or `output` when known; monkey was not sent), `not_installed_or_no_launcher`, `unexpected_output` (plus `output`, the first line that is not blank, stripped, cut to 200 characters and escaped) or `not_in_front` (plus `foreground` and `timeout`); after `not_in_front` the app may still have started. Device errors propagate unchanged.

`Device.screenshot()` captures the screen with `screencap -p`, sent through the binary-safe `exec:` service, and returns the PNG bytes unchanged. It writes nothing, on the device or on this computer, and does not change the latest dump. The bytes are checked in memory first, without decoding them, as [Taking a screenshot](commands.md#taking-a-screenshot) lists: the PNG signature, a well-formed `IHDR` chunk (13 bytes of data, width and height from 1 to 2**31 - 1, a bit depth that the color type allows, standard methods), chunks that fit in the data, the placement of `PLTE` and `IDAT`, and an empty `IEND` chunk at the end; checksums (except the fixed one of `IEND`) and pixels are not checked. Empty output, a cut-off image or other data raises `ScreenshotFailedError` (`screenshot_failed`, exit code 16), whose message says that the screen may forbid screenshots (for example a private browser tab) and that its structure can still be dumped; `details` hold `reason` (`empty` or `invalid`) and `bytes`. A screen that forbids screenshots gives empty output on older Android, but a mostly black image on newer Android; that is a valid PNG and is returned. `Device.display_for_image(width, height)` returns the display size that `dump` reports (from `wm size`), turned to the orientation of an image of that size, or `None` when `wm size` cannot be read. To save an image, open a new file in create-only mode (`open(path, "xb")`) so that nothing is overwritten; `uiprobe screenshot` does this and its checks are in [Taking a screenshot](commands.md#taking-a-screenshot).

```python
from uiprobe import Device, ScreenshotFailedError

device = Device()
try:
    png = device.screenshot()
except ScreenshotFailedError as error:
    print(error.message)  # the structure can still be dumped
else:
    with open("screen.png", "xb") as file:  # "xb" fails when the file exists
        file.write(png)
```

`uiprobe.preview(device, package, policy=None)` is the Python form of `uiprobe crawl PACKAGE`. It returns a `uiprobe.Preview` with `package`, `screen` (the `Screen` that was judged), `foreground` (the package in front, or `None` when unknown), `keyboard_shown` (`True`, `False` or `None` when unknown) and `judgement` (a `uiprobe.guards.Judgement`: `pressable` and `skipped` are tuples of decisions, each with `element`, `point`, `reasons` and `details`). `policy` is `None`, which means `uiprobe.Policy()`, or a `Policy`; `Policy(...).with_deny_words(words)` adds deny words, and `Policy(tap_unlabeled=True)` allows unlabeled elements. `Policy(skip_number_only=False)` and `Policy(skip_toggles=False)` turn off the `number_only` and `toggle` rules (both default to `True`, meaning the rule applies). `Policy(refuse_dialog_confirm=False)` drops only the `dialog_confirm_button` reason, `Policy(skip_irreversible=False)` turns off the `irreversible_screen` reason (`Policy(irreversible_phrases=...)` sets its phrases), `Policy(edges=(top, bottom, left, right))` sets the screen-edge sizes in pixels (the default `None` keeps the API 36 sizes, and an explicit `avoid` wins) and `Policy(min_visible_px=N)` (default 8) sets the smallest visible size that the judging uses; `Screen.tap_point`, `Screen.find` and `Screen.visible_bounds` keep 8. `with_deny_words` keeps all of these. `uiprobe.settings.policy_from_settings(settings, *, extra_deny=(), tap_unlabeled=None)` builds the `Policy` that the settings describe, as `crawl` does: `settings` comes from `uiprobe.settings.load_settings(path)` (a `SettingsError`, a `ValueError`, when the file is unreadable or invalid), `extra_deny` adds words like `--deny`, and `tap_unlabeled=True` forces the rule for this policy like `--tap-unlabeled` (`None` keeps the file's value). Nothing is pressed or launched and no file is written on this computer (the dump writes its own temporary file on the device, tries to remove it afterwards, and if the removal fails the file can stay on the device). The function acts on whatever is showing now: it reads `device.dump()`, then `device.foreground()`, then `device.keyboard_shown()`, and judges the screen. A foreground other than `package`, or an unknown one, gives every candidate `outside_target_app`, except on a screen over the element limit, where every candidate gets only `screen_too_large`. `package` must be a `str` (`TypeError` otherwise) of two or more dot-separated segments, each an ASCII letter followed by ASCII letters, digits or underscores, at most 255 characters (`ValueError` otherwise); a `policy` of another type raises `TypeError`. Both are checked before the adb server is contacted. Device errors propagate unchanged.

```python
from uiprobe import Device, Policy, preview

result = preview(Device(), "com.example.app", Policy().with_deny_words(["coupon"]))
for decision in result.judgement.pressable:
    print(decision.element.id, decision.point)
for decision in result.judgement.skipped:
    print(decision.element.id, decision.reasons)
```

Failures that involve the device or the adb server raise a subclass of `uiprobe.UiprobeError`.

## Crawling from Python (alpha)

`uiprobe.crawl_run` (the function `crawl` of `uiprobe.crawl_driver`) runs a pressing crawl and records it in a new run folder. It is alpha and not in the command line yet. **It presses on the selected device**: it launches the app, taps elements that the guards allow, presses BACK, and relaunches the app (`am force-stop`, then start), which can lose unsaved state. Read [Safety](safety.md) first.

```python
from uiprobe import Device, Policy, crawl_run
from uiprobe.crawl import Limits

result = crawl_run(
    Device(),
    "com.example.app",
    "runs/first",
    policy=Policy().with_deny_words(["coupon"]),
    limits=Limits(),
)
print(result.stop_reason, result.screens, result.actions, result.out)
```

`crawl_run(device, package, out, *, policy, limits, screenshots=False, allow_real_device=False, settle=1.0, stop=None, clock=time.monotonic, sleep=time.sleep)` returns `CrawlResult(out, stop_reason, screens, actions)`.

- Order: the arguments are checked (`TypeError`, `ValueError`), then the device is pinned and checked, then the run folder is made, then the app is started. Nothing is written and no input is sent before the first two pass (the device check itself reads one system property). Pinning (`Device.pin_transport`) keeps every later request on the adb transport the device was chosen on (`host:transport-id:N`), and the emulator check already goes through it, so a device that later takes the same serial receives nothing: its requests fail and the run ends with `error`. The device's identity (`ro.kernel.qemu`, `ro.serialno` and `ro.build.fingerprint`, read in one command) is kept, and before every action and every read of the screen the run checks that the adb server still lists the pinned transport with the same serial and that the identity through it is the same (and, unless `allow_real_device=True`, still an emulator); a restarted adb server numbers its transports anew, so this is what catches another device behind the same number. If not, the run ends with `error` (`DeviceNotFoundError`, `details.reason` `device_changed`). A device changed in the instant between that check and the next request is not caught. A server that reports no transport id, or an identity that cannot be read, raises `AdbError` before anything is written. All this holds with `allow_real_device=True` too. Unless `allow_real_device=True`, the device must answer that it is an emulator; a device that does not, or whose check cannot be read, raises `NotEmulatorError` (`not_emulator`, exit code 17) with nothing written and no input sent; `details["error"]` names the error of an unreadable check. A run folder that exists raises `RunFolderError` before anything is sent.
- What is sent: only the first launch, taps at the points the engine chose, BACK and relaunches. Never text, long presses, swipes or other keys. Each action is written to `transitions.jsonl` before it is sent and is sent once, never retried. The first launch does not force-stop the app, so it continues an existing task: if the app already has screens in its back stack, the depth limit counts from the screen that is showing, not from the bottom of the stack. Force-stop the app first for a clean start. A launch after which the app is not in front (a permission dialog or a splash screen of another package holds the focus) does not end the crawl: it is noted in `summary.txt` and the engine goes on from what it sees. A launch that cannot start the app at all (not installed, no launcher) ends the crawl with `error`. The record format is in [The run folder](run-folder.md).
- Every action passes one gate right after its start line is written and right before it is sent. The gate first asks `stop` and the clock, then checks the pin (above), then reads the device again, and does not send when something it needs cannot be read or has changed: then the start line gets an end line with `not_sent: true` and a `reason`, and nothing is sent. After its decision nothing else runs (no call of `stop`, no other read) before the input is sent.
  - Any action: not when `stop` returns `True` (`stopped`; once it has returned `True` it counts as `True` for the rest of the run) or the time limit has passed (`time_limit`).
  - A tap: the focused window is read, the screen is dumped again, then the foreground app, the focused window and the keyboard are read, so the reads nearest the press come last. The engine re-checks the tap on that dump (`changed_before_press`); the soft keyboard must be known to be hidden (`keyboard_unknown`, `keyboard_shown`); the window that has input focus must be owned by the app both before and after the dump (`focus_unknown`, `focus_other`: the notification shade, a system dialog or another app's window holds the focus) and must be the same window both times (`focus_changed`), so that the dump shows that window (uiautomator dumps the focused window: seen with the notification shade on API 24, 30 and 36; not checked with an app's own dialog). The owner is the `package=` that the system writes in the window's block of `dumpsys window windows`, not the window title, which an app chooses; this form was captured on emulators at API 24, 30 and 36 and is assumed for the other versions. Where it cannot be read, the crawl does not tap.
  - BACK and relaunch: the foreground app and the focused window (owner and title; and for BACK the keyboard) must be readable (`foreground_unknown`, `focus_unknown`, `keyboard_unknown`) and the same as when the action was chosen (`changed_before_send`). The engine has already counted a BACK or relaunch it returned, so when the gate does not send one, the run ends with the stop reason `not_sent` (or `interrupted` or `max_duration` when that is why) and `summary.txt` says which check refused it. A device whose readings are not steady can therefore end runs early.
  - A relaunch sends `am force-stop` and then the launch, with `stop` and the time limit asked again in between; when they end the run there, only the force-stop was sent, the end line has the reason `start_not_sent` and `summary.txt` says so.
  - A tap is reported to the engine as sent only after it was sent without an error; a tap that was refused, or whose sending failed, is never reported.
  - When `stop` or the time limit holds an action back, the run ends right there, without another read of the device.

What the checks cover, and what they cannot: right before an action is sent, the gate has, in this order, (1) asked `stop` and taken the time once, (2) checked through the pinned transport that the device's identity is unchanged, (3) read the focused window, dumped the screen (tap only), and read the foreground app, the focused window and the keyboard, and (4) decided; nothing runs between the decision and the input. In addition, while the transport is pinned, every request to the device is preceded by a request to the adb server that checks the pinned transport still lists the same serial. adb cannot check and send in one step, so the following remain:

- The device, the screen or the focus can change in the instant between the last check or read and the request that follows it (another device behind a restarted server, a dialog, the notification shade). Nothing can be done about that instant from outside the device.
- An emulator made from the same image, with the same serial, behind the same transport number, has the same identity (on the emulators checked, `ro.serialno` was the same for all of them, and `ro.build.fingerprint` differed only between versions), so it cannot be told apart.
- The time limit is looked at once, before the gate's reads, so an action can go out after the limit by up to the time those reads take.
- Another app that covers the screen only while a screenshot is taken is not caught (see `screenshots`).
- `clock` must give seconds of at least 0 and below `2**40`, such as `time.monotonic`. A value outside that range raises `ValueError`: before the run folder is made for the first value, and as an `error` run later. A screen whose element ids are not unique is recorded as a failed dump.
- `settle` is the pause in seconds after a tap or BACK; it ends early at the time limit and when `stop` returns `True` (checked every 0.1 seconds). `clock` and `sleep` replace the clock and the pause of the crawl only; the wait for the app to come to the front inside `Device.launch` (up to 10 seconds) uses the device's own clock. `screenshots=True` also saves a screenshot of each new screen; one that cannot be taken, or after which the app is not in front, is noted in `summary.txt` and the crawl goes on. Another app that covers the screen only while the image is taken and is gone again when the foreground is read afterwards is not caught.
- `stop` is called between actions, in the gate and during the pause; when it returns `True` the crawl ends with the stop reason `interrupted`, and an action already written is closed as not sent.
- Ending: the engine's stop reason (`exhausted`, `max_actions`, `max_duration`, `relaunch_limit`, `keyboard_stuck`, `dump_failed_repeatedly`) or `not_sent` (see the gate) is returned. For an error of uiprobe, adb or the device that prevents going on, `run.json` is written with `error` (the error code is in `summary.txt`) and the error is raised again. An exception that is not a uiprobe error is recorded the same way with the code `internal_error`. `CrawlResult.screens` counts the target screens observed, `CrawlResult.actions` the start lines that are complete on disk (counted by the writer, in the same marked block as the write), including those closed as not sent; the last one may not have reached the device if the run ended right then. When a write of the run folder itself fails (`RunFolderError`), the writer refuses further writes, so `run.json` is not written and the error is raised. For Ctrl+C (`KeyboardInterrupt`), `run.json` is written with `interrupted`; if `stop` is given and returns `True` at that moment and `run.json` was written, `crawl_run()` returns with `interrupted`, otherwise the interrupt is raised again (for example when the interrupt broke a write, so that `run.json` cannot be written). The library never swallows an interrupt that nobody asked to end the crawl.
