# Settings file

uiprobe keeps its crawl defaults in a settings file, `uiprobe.toml`, which uiprobe writes with every default spelled out and which you edit freely. Removing a default from the file is your responsibility. The crawl refuses to start without the file.

`uiprobe init [PATH]` creates it, at `./uiprobe.toml` unless you give a path. It prints the path (with `--json`: `{"schema": "uiprobe.init/1", "path": "..."}`). An existing file, directory or link at that path (also a link whose target is missing) is never touched: `init` then fails with a usage error (exit 2), `PATH already exists; uiprobe never overwrites it`. On Windows a path with a colon after the drive (`uiprobe.toml:extra`, which names a stream inside a file) is a usage error too, because writing a stream changes the file it belongs to; a drive path such as `C:\work\uiprobe.toml` works as usual (a path in the `\\?\GLOBALROOT\GLOBAL??\C:\...` form is refused too; give it with its drive letter). On Linux or macOS a colon is an ordinary character and is not refused; an NTFS drive mounted there with its streams turned on (NTFS-3G with `streams_interface=windows`, for example) still reads it as a stream, so do not write to such a drive. If uiprobe cannot tell whether something is at the path (access to a folder above it is denied, for example), `init` fails with the same usage error as for a file it cannot create, and creates nothing. The file is opened create-only. On Windows that open would follow a link whose target is missing, so `init` checks the path first; a link made in the instant between that check and the open is not caught there. The command does not contact the adb server and takes no device options: `-s`, `--adb`, `--adb-server` and `--no-start-server` are refused with a usage error, before or after `init`. If writing fails after the file was created (a full disk, for example), the file stays, incomplete, because uiprobe never deletes files; the error says so, and you delete it by hand and run `init` again. The same holds for Ctrl+C after the file was created: the exit status stays 130, and the message names the file (a Ctrl+C in the instant right after the file is created, before writing starts, may only say "interrupted"). The file is UTF-8 with LF line ends; the Japanese words stay readable.

**What uses the file.** `uiprobe crawl` requires it and takes from it the deny words and their exception words and phrases, the confirm words, `tap_unlabeled`, `skip_number_only`, `skip_toggles`, `skip_two_target_rows`, `skip_rows_with_buttons`, `skip_navigate_up`, `skip_sliders`, `replay_path`, `back_on_other_screens`, `scroll_lists`, the three scroll limits, `record_text`, `also_target`, `refuse_dialog_confirm`, `refuse_irreversible_screens`, the irreversibility phrases, the edge sizes and `min_visible_px` (`--config PATH` names another file; `--deny` and `--tap-unlabeled` change one run). `uiprobe key` takes the refused keys from it when `--config PATH` is given or `./uiprobe.toml` exists, and needs no file otherwise. `crawl` also takes `press` and the `[limits]` (`depth`, `actions`, `minutes`) from it. With `press = true`, `uiprobe crawl PACKAGE --out DIR` presses for real without `--press`, so the file alone can start a pressing run; `--dry-run` still previews, and a device that is not an emulator still needs `--allow-real-device` on every run. Every pressing run, by `--press` or `press = true`, records into `--out DIR` when given, else into a new folder inside `runs_dir` (below), else it stops with a usage error that asks for `--out`. A pressing crawl, started by `--press` or by `press = true`, stops at the file's `[limits]`, unless `--depth`, `--actions` or `--minutes` give another value for that run. The plan printed before the first action says why the run presses and where each limit came from (see [Pressing crawl](crawl.md#pressing-crawl---press)). The generated file gives exactly the decisions of the built-in defaults.

Keys, with their defaults:

| Key | Default | Meaning |
| --- | --- | --- |
| `format_version` | `1` | The file format. Only 1 is accepted. |
| `defaults_version` | `11` | The version of uiprobe's defaults when the file was written (1 up to the current one, which is 11). |
| `record_text` | `true` | `false` keeps the texts of the screens out of the records of a pressing crawl: every element's `text`, `content_desc` and `hint` that held a value is written as an empty string and named under `hidden` (only the fields that held a value are named), `summary.txt` shows `[text not recorded]` for labels, the window title of a `covered_by_other` end line is written empty, and `run-start.json` says `"record_text": false`. `--no-record-text` does the same for one run. It cannot be combined with `--screenshots` (a picture shows the text): the run is refused with a usage error before anything starts. It is a key about the records, not about judging, so it is not under `[rules]` and the crawl decides exactly as with `true`. A password field's text is hidden whatever this says. See [The run folder](run-folder.md#what-is-recorded-of-a-screens-texts). |
| `press` | `false` | `true` makes `uiprobe crawl PACKAGE` press for real without `--press`. It still needs `--out DIR`, or `runs_dir` in the settings file, and `--allow-real-device` on every run on a device that is not an emulator; `--dry-run` previews instead. |
| `runs_dir` | not set (`uiprobe init` writes it only as a comment) | The folder that gets the run folders of a pressing crawl that has no `--out DIR`. Optional. A relative path counts from the folder that holds the settings file (as its path was given), not from the current folder; an absolute path is used as is; `~` is not expanded. It must be a non-empty string without a null character; trailing separators are dropped (`runs/` reads as `runs`, `C:\runs\` as `C:\runs`), but a root stays as it is (`/`, `C:\`), and a value made only of separators (`//`) is kept exactly as written, and a `/.` ending is refused. See **The run folder from runs_dir** below. |
| `[deny] words` | the built-in deny words | Never press an element that contains one of these words. |
| `[deny] except` | none (`except = []`) | Exception words: a deny word found completely inside one of these words, where the word stands whole in a text, description or hint, does not count (with `automatically` listed, `call` in `Automatically`), see [Crawling an app](crawl.md). Only that occurrence is excused, where the word stands whole inside one element's text with real separators around it; an element whose only hit was there is pressed, also a label such as `Bill my card automatically`, and that is the responsibility of whoever adds the word. A label split across child elements (`Turn on` + `automatically`) or text that normalization changes may still be refused; [Crawling an app](crawl.md) gives the exact condition and its limits. A word here excuses every deny word, the built-in ones and the ones you add under `words` or with `--deny`. Each entry must be one word of letters and digits without invisible characters, and must not equal a deny word: to let a deny word through, remove the deny word instead. May be left out. |
| `[deny] except_phrases` | none (`uiprobe init` writes it only as a comment) | Exception phrases, for a row whose name holds a deny word but is not the action the word is there to stop. The standard case is `Quick Share`: with `except_phrases = ["Quick Share"]`, a row named `Quick Share` is pressed, while a row named `Share`, `Share via email` or `Quick Share settings` stays refused, and `share` stays a deny word. A phrase lets a row through only when all of this holds: the row is a plain button (it is not long-clickable, checkable, scrollable, editable or a text or password field, nothing inside it is clickable or any of those, it has at most 500 elements, and no clickable element contains it); the tap lands on the row or on something inside it; its name element (the first text in the row, in the order of the screen, that has some area on the display) equals the phrase exactly, ignoring case, extra spaces and full-width letters, and nothing covers the middle of that text, not even a sibling inside the row; the only reason the row is refused is a deny word; and the row is not pressable-but-refused again when that name text is taken out and the same screen is judged once more (the check uses the normal deny matching, with its exception words). So `Quick Share` is pressed when its only problem is the `share` of its own name; any other deny word anywhere that reaches the row (its summary, its id, an element on top of it) still refuses it, and so does text that only forms a deny word next to the name once the name is out (`De` + `Quick Share` + `lete` reads `delete`: refused, an accepted over-refusal). If a screen has more than 8 such rows, no phrase applies on that screen. Every other reason (switches, confirm buttons, dialogs, text and password fields, sliders, screen edges, covered rows, permission screens, other apps, irreversible screens) refuses the row as before, and the mouse-wheel scroll never turns over such a row. In a pressing run, the start line of the tap in `transitions.jsonl` carries `"except_phrase"` with the phrase as you wrote it, and `run-start.json` lists the phrases (see [The run folder](run-folder.md)); the tap is checked again right before it is sent, and is not sent if its mark changed. The preview marks the row `(let through by except_phrases: 'Quick Share')`. Each phrase is 1 to 80 characters, has no control or invisible character and at least one letter, and two phrases that are the same after normalization are refused. A word given with `--deny` that occurs inside a phrase drops that phrase for that run. There is no command-line option for it. Optional; no new defaults version. |
| `[confirm] words` | the built-in confirm words | Labels of buttons that confirm what the screen asks. A label counts when it equals a word or starts with one followed by a non-letter (`Yes, continue`), see [Crawling an app](crawl.md). |
| `[irreversible] phrases` | the built-in phrases (`can't undo`, `cannot be undone`, `permanently`, `元に戻せません`, ...) | A screen whose text, description or hint holds one of these phrases is refused as a whole: nothing on it is pressed. Matched like deny words, see [Crawling an app](crawl.md). Only these phrases are recognized, not every wording of such a warning. Added in defaults version 2. |
| `[rules] tap_unlabeled` | `false` | Allow pressing elements with no text, description or hint. |
| `[rules] skip_number_only` | `true` | Do not press an element whose label is only a number. |
| `[rules] skip_toggles` | `true` | Do not press a switch, checkbox or radio button, or a row that holds one. |
| `[rules] refuse_dialog_confirm` | `true` | Do not press a confirm button in a dialog: a button with a confirm label, and on a dialog screen the platform dialog's positive button (resource id `button1` under `android` or the screen's own package, and anything inside it) whatever its label. One switch turns both off. |
| `[rules] refuse_irreversible_screens` | `true` | Refuse every element of a screen that holds one of the irreversibility phrases. Added in defaults version 2. |
| `[rules] skip_two_target_rows` | `true` | Do not press a row whose children hold an element with a resource id ending in `:id/two_target_divider`: an Android Settings row with a second button, such as a network row and its gear, where pressing the row itself changes the setting (the active network). The button inside is judged on its own. Expected not to fire on vendor Settings apps such as Samsung's One UI (not confirmed). Added in defaults version 3. |
| `[rules] skip_rows_with_buttons` | `false` | Do not press a row that holds a clickable element of its own. Turn it on (`skip_rows_with_buttons = true`) for vendor Settings apps whose rows have no divider id. It also refuses list rows of ordinary apps that hold their own button (a mail row with a star, a song row with a menu). Added in defaults version 3. |
| `[rules] skip_navigate_up` | `true` | Do not press the up button of a toolbar (the arrow at its top left, or an element labelled `Navigate up`). A crawl presses the rows of a sub-page first and goes back up with its own BACK; see `navigate_up` under [Crawling an app](crawl.md). Added in defaults version 4. |
| `[rules] skip_sliders` | `true` | Do not press a slider (a seek bar, a rating bar, a Material slider), a row that holds one, or an element whose press point lies on one: a tap moves the slider and changes a value, such as a vibration intensity. See `slider` under [Crawling an app](crawl.md). Added in defaults version 4. |
| `[rules] replay_path` | `true` | After a relaunch, press again the rows that were pressed before to get back down to the screen that still has rows to try (a path replay), and count a row seen with and without a badge as one row, so a row pressed while a badge was shown is not pressed again when the badge is gone. Setting `replay_path = false` returns both the path replay and the "do not press the same row twice when only a badge changed" behaviour to the earlier behaviour. See [Pressing crawl](crawl.md#pressing-crawl---press). Added in defaults version 5. |
| `[rules] back_on_other_screens` | `false` | With `true`, a pressing crawl presses BACK on a screen of another app (up to twice before it restarts the app) instead of restarting the app at once. That BACK reaches whichever window has the input focus, not necessarily the app being crawled, and a system permission dialog gets it too, listed under `also_target` or not (see [Safety](safety.md)). `--back-on-other-screens` turns it on for one run and `--no-back-on-other-screens` turns it off for one run, whatever the file says; both together are a usage error. The plan line names where the choice came from. A file written at an older defaults version reads `false`. A version 10 file must have the key; an older uiprobe refuses it. See [Pressing crawl](crawl.md#pressing-crawl---press). Added in defaults version 10. |
| `[rules] scroll_lists` | `false` | With `true`, a pressing crawl turns a mouse wheel over a list (`input mouse scroll X Y --axis VSCROLL,-N`, one way only) on a screen with nothing left to press, to reach the rows below the fold, when the device's own `input` usage lists the wheel scroll. It is off by default because the wheel is a new kind of input that an app's own view can react to; read [A wheel scroll from the crawl](safety.md#a-wheel-scroll-from-the-crawl) first. `--scroll` turns it on for one run and `--no-scroll` turns it off for one run, whatever the file says; both together are a usage error. The plan line names where the choice came from and the limits. A file written at an older defaults version reads `false`. A version 11 file must have this key. |
| `[rules] also_target` | `[]` (written by `uiprobe init` as a comment) | A list of package names, besides the app being crawled, in whose screens a pressing crawl may also press. A screen of a listed package is judged exactly like the app's own, with every guard; see [Listing more apps](safety.md#listing-more-apps-also_target) for what that allows and what stays refused. Each entry is checked like the command's `PACKAGE`; a duplicate, and the crawled app itself, are refused as a settings error (exit 2). `com.android.systemui`, the fixed home apps `com.android.launcher3`, `com.google.android.apps.nexuslauncher` and `com.sec.android.app.launcher`, and the device's own home app are refused when the run starts. The device's own home app is read once at the start, and a run whose home app cannot be read is refused (exit 2 for an unreadable answer; a read that fails at the transport level, such as `AdbError`, stops before any input with that error's own exit code, 10); a home app that changes during the run is not noticed. There is no command-line option for it. Optional in every file; added in defaults version 8. |
| `[rules] min_visible_px` | `8` | The smallest visible width and height of an element, 1 to 64. |
| `[rules] edge_top_px`, `edge_bottom_px`, `edge_side_px` | `24`, `32`, `30` | Screen-edge sizes in pixels, each 0 to 500 (the API 36 values). |
| `[limits] depth` | `5` | How deep a pressing crawl taps on one path, 1 to 50 (it does not end the run). `--depth` overrides it for one run. |
| `[limits] actions` | `300` | The most actions a pressing crawl sends (the launch, taps, BACK and restarts each count), 1 to 10000. `--actions` overrides it for one run. |
| `[limits] minutes` | `30` | The longest pressing crawl in minutes, 1 to 1440. `--minutes` overrides it for one run. |
| `[limits] scrolls_per_screen` | `10` | The most wheel scrolls a run sends on one screen (counted per container, per family of screen ids, per set of lists of the screen and per activity, so the count is shared by all pages of one activity: raise it for a single-activity app), 1 to 100. Used only with `scroll_lists`. No option overrides it. A file written at an older defaults version reads `10`; a version 11 file must have this key. |
| `[limits] scroll_amount` | `3` | The size of one wheel scroll, 1 to 10. Used only with `scroll_lists`. A file written at an older defaults version reads `3`; a version 11 file must have this key. |
| `[limits] scroll_incidents` | `2` | After this many scrolls that changed a value or opened another screen, the run scrolls no more, 1 to 100. Used only with `scroll_lists`. A file written at an older defaults version reads `2`; a version 11 file must have this key. |
| `[keys] refuse` | the device-wide keys listed under [Pressing keys](commands.md#pressing-keys), without the fixed keys below | Key names `uiprobe key` refuses. |
| `[keys] refuse_prefixes` | `KEYCODE_MEDIA_`, `KEYCODE_SYSTEM_NAVIGATION_`, ... | Every key whose name starts with one of these is refused. |

`[deny]`, `[confirm]`, `[irreversible]` and `[keys]` each also have `remove = []`; `[deny] remove` takes words out of both `words` and `except`. The effective list is the words in the file, plus every default that a later uiprobe version added (a default carries the defaults version that introduced it), minus the `remove` entries. So a word or phrase you delete from `words` or `phrases` stays off, a word that a later version adds applies on its own, and you keep it out by listing it under `remove`. Deny words are compared after the normalization the matching uses (case and width variants and whitespace runs are the same word). Confirm words are compared in the form the confirm matching uses, which also drops surrounding punctuation and invisible characters, so `OK!` and `OK` are the same word (also for duplicates). Irreversibility phrases are compared in the form that decides what they match: after the same normalization as deny words, with curly apostrophes read as plain ones and with spaces and separators ignored. So a phrase written with a curly apostrophe equals the same phrase with a plain one, and `can not be undone` equals `cannot be undone` (listing both is a duplicate, and removing either removes the built-in `cannot be undone`). Key names are compared exactly. `[keys] remove` takes names out of both `refuse` and `refuse_prefixes`; removing a key that a remaining prefix still covers (for example `KEYCODE_MEDIA_PLAY` while `KEYCODE_MEDIA_` is listed) has no effect and gives a warning.

**The run folder from runs_dir.** When a pressing crawl has no `--out DIR` and the file sets `runs_dir`, the run records into a new folder inside the folder `runs_dir` names. That folder must already exist, be a folder and not itself be a link or (on Windows) a junction: only the last part of `runs_dir` is checked so, and links and junctions in the parts above it are followed, as for `--out`. Other reparse points that Windows resolves by itself, such as cloud-file placeholders, count as ordinary folders. uiprobe never creates that folder, and a missing one stops the run with a message that says to create that folder or add `--out DIR`. The run folder is named `PACKAGE-YYYYMMDD-HHMMSS` in local time, without a time zone; when that name is taken by anything (a file, a folder or a link), `-2`, `-3` and so on up to `-99` are tried, which also covers two runs in the same second or a clock change, and when all are taken the run stops with an error. Only the run folder is made, create-only, so nothing is reused or overwritten; a folder that another program makes under the chosen name before the run makes it ends the run before any action, without writing into it. `uiprobe init` writes the key as a comment only, `# runs_dir = "uiprobe-runs"` with a line above it that says what it is for, so a new file still asks for `--out DIR`; remove the `#` and create the folder to use it. Accepted limit: another program running as the same user can replace the `runs_dir` folder, or the new run folder, with a link between uiprobe's check and its use, so the records can land somewhere else; the same holds for `--out` today. Making the folder and writing its files through an open handle of the folder (`dir_fd`) would close that gap and is a possible later change.

**Files written by an older uiprobe.** A file keeps working when uiprobe adds defaults. A file with `defaults_version = 1` (written before defaults version 2) has no `[irreversible]` table and no `[rules] refuse_irreversible_screens`; it is read as if the table held no phrases and the rule were `true`, so all the built-in irreversibility phrases apply, and so do the deny words that version 2 added (`restart`, `undo`, `やり直`, `元に戻`). To keep any of them out, list it under `remove` of its table (you may add an `[irreversible]` table with only `remove`, or with `phrases`, to such a file); to turn the rule off, add `refuse_irreversible_screens = false` under `[rules]`. `[deny] except` may be left out of any file; a file without it decides exactly as before, because uiprobe has no built-in exception words. It came without a new defaults version for that reason: it adds no default. When present, these entries are checked like all others. A file with `defaults_version` 1 or 2 has no `skip_two_target_rows` and no `skip_rows_with_buttons`; it is read as if they were `true` and `false`, and you may add either key to it. Version 3 added only these two rules (no words, phrases or keys). A file with `defaults_version = 3` must have both; an older uiprobe refuses it: its message says that `defaults_version` must be from 1 to 2, not 3. A file with `defaults_version` 1, 2 or 3 has no `skip_navigate_up` and no `skip_sliders`; it is read as if both were `true`, and you may add either key to it (`skip_navigate_up = false` keeps the up button pressable, `skip_sliders = false` keeps sliders pressable). Version 4 added only these two rules (no words, phrases or keys). A file with `defaults_version = 4` must have both. Version 5 added only the rule `replay_path`. A file with `defaults_version` 1, 2, 3 or 4 has no `replay_path`; it is read as if it were `true` (always on, old files included), and you may add `replay_path = false` to it to turn the replay and the badge handling off. A file with `defaults_version = 5` must have the key. Version 6 added only the top-level key `record_text`. A file with `defaults_version` 1 to 5 has no `record_text`; it is read as if it were `true`, and you may add `record_text = false` to it. A file with `defaults_version = 6` must have the key. Version 7 added only deny words (no rules or keys): `forget`, `disconnect`, `unpair`, `turn off`, `revoke`, `eject`, `unmount`, `unlink`, `deactivate`, `切断`, `接続を解除`, `ペアリングを解除`, `オフにする`, `取り出`, `マウント解除` and `リンク解除`. A file with `defaults_version` 1 to 6 gets them without listing them; list one under `[deny] remove` to keep it out. If such a file lists one of these words under `[deny] except` (for example `except = ["forget"]`, which was accepted before version 7), it is now refused at load, because an exception cannot equal a deny word in use; the message names both ways out: drop the word from `[deny] except` (it is a default deny word now), or add it to `[deny] remove` (which takes it out of both `words` and `except`). Version 8 added only the rule `also_target` (no words, phrases or keys); it is optional in every file, so a file written at any version reads as `also_target = []` unless it lists packages, and `uiprobe init` writes it as a comment line under `[rules]`. Version 9 added only confirm words (no rules or keys): `turn on`, `enable`, `オンにする` and `有効にする`. A file with `defaults_version` 1 to 8 gets them without listing them; list one under `[confirm] remove` to keep it out. They are dialog-only: they give `dialog_confirm_button` on dialog screens and never the screen-wide `confirm_button`. Version 10 added only the rule `back_on_other_screens` (no words, phrases or keys). A file with `defaults_version` 1 to 9 has no `back_on_other_screens`; it is read as if it were `false` (the default does not change), and you may add `back_on_other_screens = true` to it. A file with `defaults_version = 10` must have the key. Version 11 added only the rule `scroll_lists` (`false`) and the `[limits]` keys `scrolls_per_screen` (10), `scroll_amount` (3) and `scroll_incidents` (2) (no words, phrases or keys). A file with `defaults_version` 1 to 10 has none of them; it is read with those values (so it never scrolls), and you may add any of them. A file with `defaults_version = 11` must have all four. `uiprobe init` writes `defaults_version = 11` with every table and key, and `except = []`. An older uiprobe refuses such a file: its message says that `defaults_version` must be from 1 to 10, not 11. (A uiprobe older than defaults version 8 also refuses a file that lists `also_target`, as an unknown key; one of version 8 or later reads it. The comment line loads in every version.) `press` and `[limits]` are in the file since version 1, so their use by the pressing crawl came without a new defaults version: a file written by an older `uiprobe init` says `press = false` and does not start pressing, and the `[limits]` written in it (depth 5, actions 300, minutes 30, unless you changed them) now apply to every pressing crawl that gives no option for them. The previous version used depth 3, actions 30 and minutes 5 for `crawl --press` and did not read the file's limits. `runs_dir` came without a new defaults version too, like `[deny] except`: it is optional and adds no default, so a file without it reads exactly as before. An older uiprobe refuses a file with an active `runs_dir` line as an unknown key; the comment-only line that `uiprobe init` writes loads in every version. Neither row rule catches a row with no structural sign, for example a saved Wi-Fi network row whose press reconnects: it has no divider and no button inside.

These keys are fixed: `KEYCODE_POWER`, `KEYCODE_SLEEP`, `KEYCODE_SOFT_SLEEP`, `KEYCODE_LOCK`, `KEYCODE_CALL`, `KEYCODE_ENDCALL`, `KEYCODE_HEADSETHOOK`, `KEYCODE_TV_POWER`, `KEYCODE_AVR_POWER` and `KEYCODE_STB_POWER`. They are always refused and are not in the file; listing one under `[keys] remove` is accepted but has no effect and gives a warning.

The options of [the commands](commands.md) are not settings. Never in the file: `--allow-real-device` for each run on a real device, permission screens, password fields, typing, staying inside the target app, the re-read before a press and Ctrl+C.

The reader is strict. It refuses unknown tables or keys, wrong types (a boolean where a number is expected too), numbers out of the ranges above, words that deny matching rejects, key names that do not match `KEYCODE_[A-Z0-9_]{1,40}`, duplicate entries, and a missing table or key (only the `remove` lists may be left out, see below for older files). It reads a regular file of at most 1 MiB as UTF-8 (a BOM is accepted, UTF-16 is refused). The path is opened once, read-only, and everything after that uses the opened file, not the path: the checks (regular file, size), the bytes and the check for a change.

Prevented on all systems: the bytes always come from the one file that was opened and checked; never more than 1 MiB + 1 byte is read, so a file that keeps growing is cut off and refused; a change during the read (size, modification time or change time) is refused with "the file changed while it was read; try again"; and a path that names another file after the read (a symbolic link or a folder switched, a file replaced or removed; on Windows an open file cannot be deleted or replaced, so only the other cases can occur there) is refused the same way. A settings file that is a symbolic link is read normally. On Linux and macOS the open does not wait for a FIFO writer and uses `O_NOCTTY` (so opening a terminal device cannot make it the controlling terminal), so a FIFO or a device at the path is refused as "not a regular file" before any read. A file on a stalled network or FUSE mount can still make the read wait. On Windows there is no non-blocking open: an ordinary path cannot name a pipe, and a device name such as `CON` is refused by the check of the opened file before any read. The change time is the creation time on Windows, so a same-size rewrite that restores the modification time is caught on Linux and macOS when the file system records a newer change time (not on file systems with coarse timestamps), but not on Windows.

What remains: the path is resolved once, at the open. A symbolic link or folder that is switched just before the open makes uiprobe read the file the path named at that moment (that file is still fully checked). A switch that is undone before the end of the read cannot mix bytes any more, because only the opened file is read. Anyone who can switch the path can already make it name a file with any content.
